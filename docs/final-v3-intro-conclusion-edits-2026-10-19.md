- 기준: `final-v3-compact.docx`. 수정은 서론 2~3문단과 결론 두 문단뿐이다. 서론 1문단은 바뀐 곳이 없다.

## 서론

### 2문단 — [2]의 표현과 한계

| | 문장 |
|---|---|
| 전 | 한편 플래시 칩에서 … 알려져 있으며[2][3], 상용 SSD를 호스트에서 측정한 연구[2]는 이를 꼬리 지연시간의 주원인으로 **추정하였으나 장치 안의 단계별 대기를 직접 측정하지는 않았다.** |
| 후 | … 알려져 있으며[2][3], **상용 SSD 연구[2]는 이를 꼬리 지연시간의 주원인으로 결론지었으나 호스트에서 본 지연시간만으로는 장치 안의 단계별 대기를 직접 볼 수 없었다.** |

**이유:** [2]는 GC를 제외하는 등 통제 실험으로 읽기-쓰기 간섭이 주원인이라고 결론지었다. "추정"은 [2]를 낮춰 쓴 것이 된다. 우리와의 차이는 "호스트 지연만으로는 장치 안의 단계를 직접 볼 수 없다"는 점이다.

### 3문단 — 쓰기 조건, 용어 풀이, 차별점, 수치 정리

| | 문장 |
|---|---|
| 전 | … 계측하여, **쓰기 요청이 NAND의 기록 속도보다 빠르게 계속 도착하는** 지속 쓰기 부하에서 꼬리 지연시간을 단계별로 분해하였다. 분석 결과, 읽기 요청을 한 번에 하나씩 보낼 때(QD1) R-Buf로 버퍼 대기를 없애도 펌웨어 내부 지연시간의 p99는 17.6ms에서 9.1ms까지만 줄었다. 남은 꼬리 지연시간의 97%는 die queue에서 **앞선** 쓰기 요청을 기다리는 시간이었으며, **이 대기는 선행 요청 하나당 약 0.58ms씩 늘었다.** |
| 후 | … 계측하여, **쓰기 요청을 속도 제한 없이 계속 보내는** 지속 쓰기 부하에서 꼬리 지연시간을 단계별로 분해하였다. **이 부하는 기존 연구의 실험과 쓰기 요청 크기 등이 달라 R-Buf의 개선 폭도 다르므로(3장), 본 논문은 개선 폭이 아니라 남는 지연의 위치를 본다.** 분석 결과, 읽기 요청을 한 번에 하나씩 보낼 때(QD1) R-Buf로 버퍼 대기를 없애도 펌웨어 내부 지연시간의 p99**(요청의 99%가 이 값 이하인 지연시간)**는 17.6ms에서 9.1ms까지만 줄었고, 남은 꼬리 지연시간의 97%는 **NAND 칩인 die마다 있는 요청 대기열(die queue)**에서 **선행** 쓰기 요청을 기다리는 시간이었다. **기존 연구는 펌웨어 안에서 평균만, 상용 SSD 연구는 호스트에서 지연시간만 보았으나, 본 논문은 이를 펌웨어 안에서 읽기 요청마다 직접 측정하였다.** |

**이유**
- **조건 차이 문장(추가):** 서론 1문단은 기존 연구가 8.8배에서 1.1배로 줄였다고 소개하는데, 우리 R-Buf는 3장에서 17.0배에서 8.3배다. 독자가 3장 끝까지 가야 이 차이를 만난다. "우리 구현이 약해서 남는 것 아닌가"라는 첫 의문에 서론에서 답하고, 본 논문의 대상이 개선 폭이 아니라 남는 지연의 위치임을 밝힌다. 기존 연구는 4KB 쓰기, 우리는 16KB 쓰기라는 점만 근거로 썼다. 기존 연구가 쓰기를 제한했는지는 확인하지 못해서 "속도 제한 없이"는 우리 조건으로만 썼다.
- **p99와 die queue 풀이(추가):** 2장에서야 정의되는 용어가 서론에 먼저 나온다. 첫 등장에서 한 구절로 푼다. "펌웨어 내부 지연시간의"는 범위를 위해 그대로 남겼다.
- **차별점 문장(추가):** 새로움이 2문단에 암시로만 있었다. 3문단 끝에 "펌웨어 안에서 읽기 요청마다 직접 측정"을 명시한다. 2문단과 내용이 일부 겹치므로 분량이 문제되면 2문단의 마지막 구절을 줄인다.
- **"0.58ms씩" 삭제:** 요약·결론 수치 중복을 줄인다(요약과 4장에 남음).
- **"앞선" → "선행":** 4장의 "선행 요청 수"와 용어를 맞춘다.
- **"NAND의 기록 속도보다 빠르게 도착하는" 삭제:** 이 설명은 요약에 있다. 서론에서는 우리가 쓰기를 제한 없이 보낸다는 조건 자체를 쓴다.

## 결론

### 1문단 — 수치 삭제, [2]·[1] 표현

| | 문장 |
|---|---|
| 전 | **읽기 요청을 한 번에 하나씩 보낼 때(QD1) R-Buf로 버퍼 대기를 없애도 펌웨어 내부 지연시간의 p99는 17.6ms에서 9.1ms까지만 줄었다. 남은 꼬리 지연시간의 97%는 … 이 대기는 선행 요청 하나당 약 0.58ms씩 늘었다.** 이는 R-Buf가 버퍼 단계의 대기를 없앤 뒤 … 확인한 것으로, 상용 SSD의 호스트 측정에서 추정된 쓰기 요청 뒤의 읽기 요청 대기[2]와 같은 방향이다. 또한 기존 연구[1]는 채널 수준의 읽기 우선으로 읽기 요청이 플래시 칩 단계에서 쓰기 요청의 간섭을 받지 않는다고 **보았으나,** 본 논문이 사용한 펌웨어에서는 같은 die queue 안에서 읽기 요청이 앞선 쓰기 요청 뒤에서 기다렸다. |
| 후 | **본 논문은 R-Buf 적용 후 남는 읽기 요청의 꼬리 지연시간이 어느 처리 단계에서 생기는지를 펌웨어 안에서 요청별로 분해하여, 지속 쓰기 부하의 QD1에서 그 대부분이 버퍼가 아니라 die queue에서 선행 쓰기 요청을 기다리는 시간임을 확인하였다.** 이는 **상용 SSD 연구[2]가 호스트 측정으로 주원인이라 결론지은** 쓰기 요청 뒤의 읽기 요청 대기와 같은 방향이다. 기존 연구[1]는 **R-Buf와** 채널 수준의 읽기 우선으로 읽기 요청이 플래시 칩**까지** 쓰기 요청의 간섭을 받지 않**게 된다고 서술하였다.** 본 논문이 사용한 펌웨어에서는 같은 die queue 안에서 읽기 요청이 앞선 쓰기 요청 뒤에서 기다렸**으며, [1]의 펌웨어가 같은 구조인지는 확인하지 못했다.** |

**이유**
- **수치 삭제:** 같은 수치(17.6, 9.1, 97%, 0.58)가 요약, 서론 3문단, 결론에 세 번 나온다. 결론은 수치 없이 "무엇이 확인되었고 어떤 의미인가"만 쓰고, 수치는 요약·서론·4장에 둔다.
- **"추정된" → "결론지은":** 서론 2문단과 같은 이유다.
- **"보았으나" → "서술하였다":** [1]을 반박하는 어조를 낮춘다. 원 논문 결론("read priority mechanism at the flash channel, reads do not experience any interference from writes … to the flash chips")을 요약한 것이므로 사실 관계는 같다.
- **"[1]의 펌웨어가 같은 구조인지는 확인하지 못했다" 추가:** [1]의 펌웨어 코드를 확인하지 않았다. 앞 문장이 [1]을 반박하는 것처럼 읽히지 않도록 범위를 밝힌다. "본 논문이 사용한 펌웨어에서는"만 쓰는 것보다 정직하다.

### 2문단 — 향후 연구 문장

| | 문장 |
|---|---|
| 전 | … 향후에는 die queue에서 읽기 요청을 대기 중인 쓰기 요청보다 먼저 처리하는 스케줄링의 효과와 쓰기 쪽 비용을 평가할 **계획이다.** |
| 후 | … **남은 대기가 die queue의 FIFO 순서에서 비롯되므로,** 향후에는 die queue에서 읽기 요청을 대기 중인 쓰기 요청보다 먼저 처리하는 스케줄링의 효과와 쓰기 쪽 비용을 평가할 **필요가 있다.** |

**이유**
- 앞 문장 없이 향후 연구가 나오면 결과와 이어지지 않는다. 결과(대기가 선행 요청 수에 비례)에서 다음 단계가 나오게 한 구절을 붙인다.
- "계획이다"는 약속처럼 읽힌다. 스케줄링은 실험하지 않았으므로 "필요가 있다"로 낮춘다.
